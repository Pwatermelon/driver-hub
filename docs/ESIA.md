# Интеграция Driver Hub с Госуслугами (ЕСИА / Цифровой профиль)

Документ для подготовки **заявки на подключение ИС** и полного боевого контура верификации водителя.

Заявка на подключение: [ESIA_APPLICATION.md](./ESIA_APPLICATION.md)

---

## 1. Цель интеграции

Driver Hub — реестр водителей для логистических компаний. Через Госуслуги (ЕСИА) нужно:

1. Подтвердить, что пользователь — реальный гражданин с **подтверждённой** УЗ.
2. Получить идентифицирующие ПДн (ФИО, дата рождения, СНИЛС, ИНН, контакты).
3. Получить данные **водительского удостоверения** (серия, номер, категории, сроки, кем выдано).
4. По возможности — актуальные сведения ВУ из ГИБДД через Цифровой профиль / СМЭВ.

Без этого верификация остаётся mock/OCR и не имеет юридической силы для HR-проверок.

## 2. Что именно запрашиваем у ЕСИА (для заявки)

### 2.1. Обязательные scope (минимум для MVP)

| Scope | Зачем Driver Hub | Поля в системе |
|---|---|---|
| `openid` | Вход, `oid` субъекта | `drivers.esia_oid` |
| `fullname` | Фамилия, имя, отчество | `last_name`, `first_name`, `middle_name` |
| `birthdate` | Дата рождения | `birth_date` |
| `gender` | Пол (контроль/аналитика) | не критично, желательно |
| `snils` | СНИЛС | `snils` |
| `inn` | ИНН | `inn` |
| `mobile` | Телефон | `phone` |
| `email` | Email | `email` |
| `id_doc` | Паспорт РФ (доп. идентификация) | внутренний контроль |
| `drivers_licence_doc` | Водительское удостоверение | `driver_licenses.*`, `categories` |

Строка для заявки / env:

```text
openid fullname birthdate gender snils inn mobile email id_doc drivers_licence_doc
```

### 2.2. Данные ВУ, которые должны попасть в профиль

| Поле | Источник ЕСИА / документа | Куда пишем |
|---|---|---|
| Серия ВУ | `drivers_licence_doc` / ЦП | `driver_licenses.series` |
| Номер ВУ | то же | `driver_licenses.number` |
| Дата выдачи | то же | `driver_licenses.issue_date` |
| Срок действия | то же | `driver_licenses.expiry_date` |
| Категории | то же | `driver_licenses.categories`, `drivers.categories` |
| Кем выдано | то же | `driver_licenses.issuer` |
| Признак подтверждённой УЗ | профиль (`trusted` / уровень УЗ) | `verification_status=verified` |

### 2.3. Желательно через Цифровой профиль гражданина (ЦПГ)

| Документ / тип сведений | sysname / код (ориентир) | Зачем |
|---|---|---|
| ВУ из цифрового профиля | `RF_DRIVING_LICENSE` | Актуальная карточка ВУ |
| Сведения ГИБДД по ВУ | `GIBDD_DRIVER_LICENSE` | Проверка действительности |
| Паспорт РФ | `RF_PASSPORT` | Доп. сверка личности |

Для ЦПГ нужны: регистрация целей (`purposes`), согласие гражданина, `permissions` / `actions`, правовое основание.

### 2.4. Что ЕСИА НЕ даёт «из коробки» (отдельные контуры)

Это **не** включать в заявку на обычные scope ЕСИА как будто они уже доступны. Нужны отдельные ВС СМЭВ и основания:

| Данные | Канал | Модель в Driver Hub |
|---|---|---|
| Лишение / ограничение права управления | СМЭВ ↔ ГИБДД | `license_suspensions` |
| Штрафы ГИБДД | СМЭВ / сервисы ГИБДД | `fines` (`source=gibdd`) |
| Справка о судимости / отсутствии | СМЭВ ↔ МВД | `criminal_records` |
| Медсправка водителя | загрузка / отдельные ВС | `medical_certificates` |
| Рекомендации, жалобы, блэклист, ДТП от работодателей | только Driver Hub | бизнес-данные платформы |

## 3. Пользовательский сценарий (боевой)

```
Водитель (мобильный кабинет)
  → «Подтвердить через Госуслуги»
  → GET /api/v1/auth/esia/start
  → редирект ЕСИА /aas/oauth2/ac  (consent)
  → callback /api/v1/auth/esia/callback?code&state
  → обмен code → access_token /aas/oauth2/te
  → GET /rs/prns/{oid}?embed=(contacts.elements,documents.elements)
  → запись профиля + ВУ, verification_status=verified
  → возврат в кабинет с Hub ID / QR
```

Требование: принимать только **подтверждённую** УЗ (`trusted`). Иначе отказ с понятным текстом.

Код: `internal/esia/live.go`, `internal/esia/mock.go`, handlers `StartESIA` / `ESIACallback` / `MockESIAVerify`.

## 4. Юридические и организационные требования

1. Юрлицо-оператор ИС с подтверждённой УЗ в ЕСИА.
2. КЭП руководителя / уполномоченного (для регистрации ИС).
3. Политика обработки ПДн, согласие субъекта, цели обработки (152-ФЗ).
4. Описание ИС: назначение — верификация водителей для логистических работодателей.
5. Мнемоника ИС в СМЭВ = мнемоника в ЕСИА.
6. `redirect_uri` на проде: `https://<domain>/api/v1/auth/esia/callback` (строго совпадение).
7. Сертификат ИС: для продуктива ЕСИА обычно **ГОСТ Р 34.10-2012**.
8. Журналирование фактов доступа/обновления профиля (аудит).

## 5. Технические требования к подключению

### 5.1. Среды

| Среда | Base URL |
|---|---|
| Тест | `https://esia-portal1.test.gosuslugi.ru` |
| Прод | `https://esia.gosuslugi.ru` |

### 5.2. Endpoints, которые используем

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/aas/oauth2/ac` | Авторизация / согласие |
| POST | `/aas/oauth2/te` | Обмен code на токены |
| GET | `/rs/prns/{oid}` | Профиль (+ embed contacts/documents) |

### 5.3. Подпись

В продуктиве `client_secret` в запросах к ЕСИА подписывается по ГОСТ.  
В текущем `LiveClient` — RSA/RS256-заглушка под шлюз/стенд. Перед продом: КриптоПро / ГОСТ-engine либо ЕСИА-шлюз.

### 5.4. Переменные окружения

```env
ESIA_MODE=live
ESIA_BASE_URL=https://esia-portal1.test.gosuslugi.ru
ESIA_CLIENT_ID=<mnemonic_or_client_id>
ESIA_CLIENT_SECRET=<secret_or_unused_with_gost_sign>
ESIA_REDIRECT_URI=https://<domain>/api/v1/auth/esia/callback
ESIA_SCOPES=openid,fullname,birthdate,gender,snils,inn,mobile,email,id_doc,drivers_licence_doc
ESIA_KEY_PATH=/certs/esia.key
ESIA_CERT_PATH=/certs/esia.cer
PUBLIC_BASE_URL=https://<domain>
```

## 6. Модель доступа к данным в Driver Hub (после верификации)

- Любая **авторизованная компания** может открыть досье по Hub ID (продуктовая модель реестра).
- Публичная карточка `/drivers/{hubID}/public` — урезанные данные без полного ПДн.
- Водитель подтверждает личность через ЕСИА; компании не ходят в ЕСИА напрямую.
- Все выдачи/просмотры досье должны логироваться (аудит).

> В ранних версиях был `access_grant` от водителя. Сейчас доступ к досье для компаний открыт по Hub ID; для промышленного контура с ПДн может потребоваться вернуть явное согласие + ЦПГ permissions.

## 7. План работ по подключению

1. Юр. пакет + политика ПДн.  
2. Регистрация ИС в СМЭВ → та же мнемоника в ЕСИА.  
3. Заявка на **тестовые** scope (раздел 2.1).  
4. Настройка ГОСТ-подписи / шлюза.  
5. Интеграционные тесты на `esia-portal1.test`.  
6. Заявка на **продуктив**.  
7. (Опционально этап 2) ЦПГ документы `RF_DRIVING_LICENSE`, `GIBDD_DRIVER_LICENSE`.  
8. (Опционально этап 3) отдельные ВС СМЭВ: лишения, штрафы, судимость, медицина.
